Real‑Time Operating System, built from scratch

A custom RTOS written directly in ARM assembly, built to prove out the core mechanics that make real‑time guarantees possible: scheduling, context switching, and safe resource sharing.

Overview

Most engineers work with RTOSes like FreeRTOS or ThreadX without seeing what happens underneath. This project went the other way: build the scheduler, the context switch, and the synchronisation primitives myself, in assembly, for an ARM target — to understand exactly what an RTOS is promising when it says a task will run on time.

What I built

  • A task scheduler that decides which task runs next based on priority and readiness.
  • Context switching routines written in ARM assembly — saving and restoring register state so a task can be paused and resumed without losing its place.
  • Mutex protocols to let tasks share resources safely without corrupting shared state or deadlocking each other.

Challenge

The system was stable at its design clock speed, but became unreliable when I dropped the clock frequency — crashes appeared that weren't present before. That meant timing assumptions baked into the scheduler and context‑switch code were more fragile than they looked. I went back through the low‑level timing paths, found where the assumptions broke, and reworked the code so it held up across a range of operating frequencies rather than just one.

Outcome

A working RTOS core — scheduler, context switch, and mutexes — that meets real‑time deadlines reliably, including under reduced clock frequencies. More importantly: a concrete, first‑principles understanding of what happens between "task A" and "task B" on a real processor, which now informs how I evaluate and debug the commercial RTOSes I use day to day.
